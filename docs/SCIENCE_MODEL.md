# 과학 모형의 단순화와 정밀도

이 문서는 앱의 계산이 무엇을 정확히 하고 무엇을 단순화했는지 적는다. 교사는 학생에게 ‘학습 모형’과 ‘앱 계산’, ‘기관 자료’를 구분해 설명할 때 참고한다.

## 1. 좌표계 (`shared/phaseMath.ts`)

- 지구가 원점, **Y 가 위(황도면 북쪽)**, 황도면은 XZ 평면. 태양은 +X 방향, 햇빛은 평행광.
- 달의 공전 각도 θ 는 태양 방향에서 시작해 위에서 볼 때 **반시계** 방향으로 증가. 위치 = (r cosθ, 0, −r sinθ).
- θ = 0° 삭 → 90° 상현 → 180° 보름 → 270° 하현 → 360° 삭. 0<θ<180 차오름, 180<θ<360 기움.
- 위상각 α = 180° − θ. 원반의 밝은 비율 **k = (1 + cos α)/2 = (1 − cos θ)/2**. 달 전체 표면의 밝은 비율은 식을 제외하면 항상 1/2.
- 지구 시점은 관측자가 **지구 중심**에서 달을 보고 +Y 가 화면 위인 ‘단순화한 지구 관측 방향’. 실제 지역 하늘의 회전·고도·지평선은 계산하지 않는다. 이 기준에서 상현은 오른쪽, 하현은 왼쪽이 밝다(북반구).
- 3D 셰이딩과 2D 원반(목표·대체 화면·보고서)은 같은 규칙 `dot(normal, sunDir) > 0` 을 쓴다. 단위 테스트가 12개 각도에서 픽셀 샘플링 비율과 해석값 k 의 일치를 확인한다.

## 2. 위상 판정 (`judgePhaseAttempt`)

| 목표 유형 | 판정 | 쓰는 곳 |
|---|---|---|
| `theta` (각도 + 허용 오차) | 각 거리 ≤ 허용(보름·상현 15°, 초승 18°, 날짜 목표 25°) | 06 대표 위상, 06 날짜 목표, 05 예측 |
| `illumination` (밝은 비율 구간 + 차오름 여부) | 비율 구간 ±0.2, `waxing: null` 이면 좌우를 판정하지 않음 | 07 관측 자료(회전·시각 불확실) |
| 학생 그림 | 자동 판정 없음, 나란히 놓고 자기 평가 | 06 내 목표, 07 |

피드백은 정오 판정보다 ‘다음에 시험해 볼 것’을 제안한다. 밝은 비율만 같고 차오름/기움이 다른 경우를 따로 알려준다. 실제 사진의 회전만으로 오답 처리하지 않는다.

## 3. 식 판정 (`shared/eclipseMath.ts`)

- 물리 계산은 **km 단위 실제 값**(태양 반지름 696,000, 지구 6,371, 달 1,737.4, 태양 거리 1.496×10⁸, 달 거리 384,400)을 쓰고, 달의 **방향 단위벡터**만 학생이 조작한 (θ, 교선 방향 Ω, 기울기 i)에서 가져온다. 화면의 과장된 표시 반지름·거리는 판정에 들어가지 않는다(단위 테스트로 확인).
- 궤도: 교선 방향 N = (cosΩ, 0, −sinΩ), 궤도면을 N 둘레로 i 만큼 기울임. 달은 교선에서 φ = θ − Ω 위치.
- **월식**: 지구 본그림자 반지름 = Rₑ − d(Rₛ − Rₑ)/Dₛ, 반그림자 = Rₑ + d(Rₛ + Rₑ)/Dₛ (달 거리 d 에서 각각 약 0.72 Rₑ, 1.28 Rₑ). 달 중심의 축 거리로 개기/부분/반그림자 판정.
- **일식**: 달 본그림자 반지름 = Rₘ − x(Rₛ − Rₘ)/Dₛ (평균 거리에서 지구에 닿기 직전 음수 → 금환), 반그림자 = Rₘ + x(Rₛ + Rₘ)/Dₛ. 반그림자가 지구에 닿으면 ‘부분(지구 일부)’, 축이 지구 원반 안을 지나면 ‘중심식(개기 또는 금환)’.
- **관측 지점**: 위도·경도(경도 0° = 정오)로 지구 표면 점을 두고 그 점의 축 거리로 밤/없음/부분/금환/개기를 구분. ‘지구 어디서나 같은 일식’이 아님을 보여주기 위한 계산.
- 단순화: 평균 거리 고정(근지점·원지점 없음 → 중심식은 평균 거리 기준으로 ‘금환’이 되기 쉽다), 지구 자전·시차·대기 굴절 없음, 지구·달을 완전한 구로 가정. **실제 식 예보가 아니다.**
- 월식 때 달의 어두운 색과 붉은 기는 판정 결과의 시각화이며 대기 산란 계산이 아니다.

## 4. 기울기 실험 (11단계)

- 장면 A: i = 0° 가상 조건 → 궤도 한 바퀴를 훑으면 삭·보름마다 식.
- 장면 B: i = 5.145°, Ω 고정(직각) → 보름에 달이 그림자 위/아래를 지남.
- 장면 C: Ω 를 바꿈 → Ω ≈ 0°(교선이 태양 방향과 나란)일 때만 정렬. 실제로는 지구 공전으로 태양 방향이 바뀌므로 정렬이 1년에 두 번쯤(식 계절) 온다. 앱은 태양 방향을 고정하고 교선 방향을 돌리는 등가 표현을 쓴다.
- 달의 공전 위치만 바꿔도 항상 같은 지점에서 매달 식이 생기는 모형이 되지 않도록 Ω 를 별도 변수로 둔다(단위 테스트 ‘기울기를 5°로 두는 것만으로 매달 식이 생기지 않는다’).

## 6. 날짜와 모형의 연결

- 04의 원반은 월령을 `θ ≈ 월령/29.53 × 360°` 로 바꾼 **‘월령을 이용한 근사 모형’**이다. 정확한 천체 위치가 아니다.
- 07의 ‘참고 배치’는 Astronomy Engine 의 `Illumination(Moon)`(밝은 비율·위상각)과 `MoonPhase`(태양 기준 황경 차이 0~360°)를 쓴다. 둘은 같은 값이 아니다: `MoonPhase` 가 θ 에 해당하고 `phase_fraction` 이 k 에 해당한다.
- 앱 계산 월령(기관 키가 없을 때): 그 날 12:00 KST 기준 ‘직전 삭 이후 지난 날수’. 기관 월령의 기준 시각은 문서로 확인하지 못했으므로 화면에 그렇게 표시한다.
- 앱 계산 출몰: `SearchRiseSet` 으로 KST 날짜 00:00~24:00 안의 사건. 지역 좌표는 `shared/regions.ts` 의 대표 좌표.
- 출몰 판정: 전날·다음 날 사건을 함께 시간순으로 놓고 ‘판정 시각 이전의 마지막 사건’으로 지평선 위/아래를 정한다. 자정 넘김, 사건 없는 날(null), 결측(undefined)을 구분한다.

## 7. 계산하지 않는 것

실제 날짜의 정확한 달 위치를 3D 모형에 자동 배치하는 기능, 지역 하늘의 방위·고도, 칭동, 대기 굴절, 식 예보 날짜, 구름·날씨. 이 중 어느 것도 ‘계산했다’고 화면에 표시하지 않는다.
